# Agents HW1

Консольный агент с tool calling: получает задачу, сам выбирает инструменты, читает и меняет
файлы, запускает тесты и решает, когда закончить. Реализованы все уровни до 10 баллов.

Язык — Kotlin. Контрольный проект — Python (`workspace/`).

## 1. Установка

Требования: JDK 17+, `python3`, доступ к любой OpenAI-compatible модели.

```bash
git clone <repo> && cd agents-hw1
./gradlew installDist
alias agent="$PWD/build/install/agents-hw1/bin/agents-hw1"
```

Настройка окружения — файл `settings.json` в корне (скопируйте из `settings.example.json`,
файл в `.gitignore`):

```json
{
  "llm": {
    "baseUrl": "https://api.z.ai/api/coding/paas/v4",
    "apiKey": "ВАШ_КЛЮЧ",
    "model": "glm-5.3"
  }
}
```

Запасной вариант — локальная Ollama (`ollama pull qwen3:4b && ollama serve`):
`baseUrl: http://localhost:11434/v1`, `apiKey: ollama`, `model: qwen3:4b`.

## 2. Инструменты агента

Каждый инструмент передаётся модели с именем, описанием и JSON Schema; runtime проверяет имя
и аргументы до каждого исполнения.

| Инструмент | Аргументы | Побочный эффект | Назначение |
|---|---|---|---|
| `bash` | `command`, `cwd` | да | разрешённая команда (таймаут, лимит вывода); возвращает `stdout`, `stderr`, `exit_code` |
| `list_files` | `path` | нет | список файлов каталога |
| `read_file` | `path` | нет | чтение файла |
| `write_file` | `path`, `content` | да | создание/перезапись файла |
| `delete_file` | `path` | да | удаление файла |
| `submit_plan` | `goal`, `steps[]`, `risks[]`, ... | нет | подача плана (Plan Mode) |
| `complete_task` | `task_id`, `evidence_call_id` | нет | завершение задачи с проверяемым результатом |

## 3. Запуск агента

```bash
agent run --task "Исправь расчёт итоговой стоимости заказа, чтобы тесты проходили. \
Тесты не меняй. Сам найди нужные файлы, внеси исправление и запусти тесты."
```

Режим по умолчанию — `safe` (опасные действия требуют подтверждения). Варианты:

```bash
agent run --task "..." --mode auto      # без подтверждений (кроме delete)
agent run --task "..." --plan           # Plan Mode
agent run --task "..." --limits model=30,tools=40,effects=10,output=200000
```

## 4. Настройка policy

Файл `policy.json` лежит вне `workspace/` и защищён от инструментов агента. Пример:

```json
{
  "commands": {
    "allow": ["python3 -m unittest -v", "python3 -m unittest", "python3 --version", "ls", "pwd"],
    "deny":  ["rm", "curl", "sudo", "wget"]
  },
  "directories": {
    "allow": ["workspace"],
    "deny":  ["workspace/secret_notes"]
  },
  "journal": { "ignore": ["__pycache__/", "*.pyc"] }
}
```

Правила: разрешены только точные строки простых команд (конвейеры, `;`, `&&`,
перенаправления, подстановки и другой bash-синтаксис отклоняются целиком); запрет имеет
приоритет над разрешением; всё неразрешённое отклоняется. Разрешённые директории обязаны
находиться внутри workspace; пути канонизируются (`..` и symlink не выходят наружу).
Проверка живёт отдельно от agent loop (`policy/SafetyGate.kt`) и выполняется заново перед
каждым исполнением.

## 5. Plan Mode и утверждение плана

```bash
agent run --task "..." --plan
```

До утверждения агент может только читать (`list_files`, `read_file`) и подать план через
`submit_plan` — записи, удаления и bash отклоняются runtime'ом. План сохраняется как
структурированные данные (цель, шаги с инструментами и зависимостями, риски, допущения,
критерий готовности) вместе с `run_id`, после чего агент останавливается:

```bash
agent approve-plan <runId>   # создать задачи и начать исполнение
agent reject-plan <runId>    # отклонить план и завершить запуск
```

Утверждение плана не разрешает действия заранее: в `safe` каждое опасное действие по-прежнему
требует подтверждения.

## 6. Подтверждение действия (safe / auto)

| Действие | `safe` | `auto` |
|---|---|---|
| чтение | сразу | сразу |
| `write_file`, `bash` | подтверждение | сразу (после policy) |
| `delete_file` | подтверждение | подтверждение |

При запросе подтверждения агент сохраняет состояние и останавливается:

```bash
agent approve <runId>     # разрешить
agent deny <runId>        # отклонить
agent resume <runId>      # продолжить тот же запуск
```

После отказа модель получает результат с причиной (`user_denied`) и продолжает работу.
Разрешение не «пробивает» policy: перед исполнением выполняется полная повторная проверка.

## 7. Восстановление по run_id

Каждый запуск получает `run_id`; состояние (история, tool calls и попытки, решения
пользователя, план, задачи, бюджет, журнал) лежит в `.agent_runs/<runId>/state.json`
(атомарные записи). Перед действием с побочным эффектом сохраняется «началось», после —
результат; упавший между ними вызов считается неопределённым и молча не повторяется:

```bash
agent resume <runId>                                            # покажет неопределённые вызовы
agent resume <runId> --resolve <callId>=retry|fail|abort [--attribute yes|no]
```

`retry` — явный повтор как новая попытка того же вызова; `fail` — считать шаг неуспешным и
продолжить; `abort` — завершить с ошибкой. Повтор уже завершённого `tool_call_id` отдаёт
сохранённый результат без исполнения; другие имя/аргументы при том же id — ошибка протокола.
Имитация сбоя: `AGENT_CRASH_POINT=after_debit_before_exec|after_exec_before_save
AGENT_CRASH_CALL=<N>`.

## 8. Задачи (уровень 9)

Шаги утверждённого плана становятся задачами (id, описание, зависимости, состояние,
проверяемый результат). Задача запускается после завершения зависимостей; каждый tool call
фазы исполнения связан с текущей задачей. Завершение — только через
`complete_task(task_id, evidence_call_id)`, где evidence — успешный вызов этой же задачи,
зафиксированный runtime'ом. Просмотр состояния задач:

```bash
agent tasks <runId>
```

Задачи печатаются в stdout чеклистом:

```
=== TASKS ===
[x] s1: Inspect the project  (verified by e1)
[>] s2: Fix calculate_total
[ ] s3: Run the tests
```

## 9. Diff и откат (уровень 10)

```bash
agent diff <runId>       # изменения файлов запуска
agent rollback <runId>   # безопасный откат изменений этого запуска
```

Откат восстанавливает только файлы, изменённые этим запуском; перед ним runtime заново
проверяет policy, пути и хеши — при постороннем изменении хотя бы одного файла откат
полностью отменяется с конфликтом. Журнал охватывает создание, изменение и удаление файлов
(включая правки через bash) и работает после resume.

## 10. Тесты

```bash
./gradlew test
```

72 детерминированных теста (вместо сети — скриптованная модель `FakeLlm`, сбой имитируется
точкой отказа): agent loop и инструменты, policy/безопасность, восстановление, Plan Mode,
бюджеты, задачи с зависимостями, журнал и откат, сквозной прогон контрольной задачи.
